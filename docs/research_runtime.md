# 科研任务运行时：系统性完善设计与实现

## 1. 第一性原理与用户任务

科研智能体的核心交付物不是“看起来合理的回答”，而是一个研究者能够复核、重跑、质疑和修正的工作过程。因此本次完善以五个不可妥协的约束为起点：

1. 事实性结论必须能回到来源或原始分析；没有定位信息就只能标记为待验证建议。
2. 复杂任务必须先形成显式计划、依赖关系和资源预算，执行结果不能掩盖失败或降级。
3. 工具权限必须在模型或执行器看到工具前过滤；“允许调用”与“在哪里运行”是不同边界。
4. 科研材料、运行状态、反馈和偏好必须按用户隔离，并能够取消、恢复和审计。
5. 学习不能静默改变能力；只能从显式纠正生成待审核提案，应用行为必须由用户确认。

## 2. 原系统审计

| 模块 | 原有能力 | 根因级缺口 | 风险/瓶颈 | 本次修复 |
|---|---|---|---|---|
| `ResearchAgent` | 关键词意图识别、单工具调用、LLM 回答 | 没有计划、验证或证据契约 | 复杂问题被压成一次路由；工具结果截断后不可追溯 | 新增独立科研任务运行时；旧聊天保留为轻量入口 |
| `CoordinatorAgent` | LangGraph 条件路由到 4 个专家 | 每次只选择一个分支，不是任务分解或协作 | “多智能体”名称大于实际语义；无预算/取消/并发控制 | 科研工作台使用显式 DAG、依赖波次和统一调度器 |
| Skill Registry | 参数模式、内置技能、执行日志 | 无风险/模态/网络/写文件/超时元数据 | 任意长执行；日志保存原始科研数据；重复初始化污染分类 | 新增能力元数据、超时、输出类型检查、脱敏且有界日志、幂等注册 |
| 文献检索 | PubMed/SRA/GenBank 适配器 | PubMed 每个 PMID 单独 efetch；URL 后缀错误；返回原始 XML | N+1 网络往返、结果难以消费、连接未明确关闭 | 修复 `.fcgi`、单次批量 efetch、结构化 PMID/DOI/作者/摘要/定位链接 |
| 实验设计 | 按数据类型返回静态建议 | 未定义 estimand、偏倚控制、样本量依据或伦理门 | 模板可能被误当成正式方案 | 输出估计目标、偏倚控制、功效计算步骤、分析计划、QC、伦理和报告规范 |
| 数据/可视化 | 统计检验、火山图、热图 | 缺少输入材料模型、质控和有限值验证 | 常数列/NaN/错误 P 值可能产生无效结果；CPU 工作阻塞事件循环 | 用户隔离材料库、表格剖析、质量旗标、预览图；严格数值验证；CPU 工作移出事件循环 |
| 科研写作 | 文献 PMID 占位摘要 | 未读取来源却返回“已分析” | 形成虚构完成感和引用风险 | 无来源时明确拒绝事实性综述；写作只生成脚手架与主张—证据矩阵 |
| 学术规范 | 无统一能力 | 无引用、统计报告、因果措辞、伦理检查 | 无法在定稿前暴露高风险问题 | 本地规则检查与明确边界；不伪装成抄袭数据库查重 |
| 状态/资源 | 工作流有运行记录和取消 | Agent 调用仍为同步请求；无全局资源车道 | 长任务占用请求；多个任务争抢 CPU/网络 | 后台运行管理器、全局 4/单任务 1–4 并发、逐能力超时/重试、取消传播 |
| 学习 | 用户档案有偏好字段 | 没有证据、审核或版本生命周期 | 直接“自我改进”会把偶然错误固化 | 反馈 → 待审核提案 → 应用/拒绝/隔离；应用后仅作为内容约束，不获得工具权限 |

## 3. 对 OpenClaw 设计理念的取舍

本实现参照 OpenClaw 官方文档中可验证的运行时理念，但没有复制其个人助理的主机控制面：

- [Agent loop](https://docs.openclaw.ai/concepts/agent-loop)：把工作区准备、技能装载、提示组装、工具生命周期和会话持久化视为一个运行时契约。科研运行时对应为“计划验证 → 策略过滤 → 依赖调度 → 能力执行 → 证据聚合 → 人工复核”。
- [Tools overview](https://docs.openclaw.ai/tools)：区分“工具是可调用动作、技能是工作方法、插件是运行时扩展”。本项目将 `CapabilitySpec` 与具体 handler 分离，只有通过本次运行白名单的能力才进入执行面。
- [Sandbox vs tool policy](https://docs.openclaw.ai/gateway/sandbox-vs-tool-policy-vs-elevated)：借鉴“运行位置、工具可见性和越权提升是三种不同控制”。本版本已实现工具可见/联网策略和用户材料根目录限制；没有实现任意主机命令提升。
- [Sub-agents](https://docs.openclaw.ai/tools/subagents)：借鉴独立后台任务、受限工具面、全局并发车道、运行超时、取消树和成本意识。科研任务按依赖波次并发，但不为简单步骤复制昂贵模型上下文。
- [Media understanding](https://docs.openclaw.ai/nodes/media-understanding)：借鉴“原始附件保留、能力选择、大小/超时限制、失败后继续”的降级策略。当前支持表格、文本、JSON、PDF 和图像元数据；视觉语义模型未配置时明确说明，而不是丢失附件或猜测内容。
- [Memory](https://docs.openclaw.ai/concepts/memory)：借鉴有界、按 agent/用户隔离的记忆。本项目把会话、研究运行、材料和已审核偏好分别持久化，避免把原始长记录无界注入上下文。
- [Self-learning](https://docs.openclaw.ai/tools/self-learning)：严格采用 proposal-only 原则。纠正不会训练权重、改写活跃技能或静默改变行为；只有用户选择“应用”后，偏好才以普通内容约束参与后续计划。

科研场景比通用个人助理额外强调来源质量、研究设计、统计解释、伦理与报告规范。因此没有引入“全权限自主行动”，而是把高影响结果强制放在人类复核门之后。

## 4. 完善后的架构

```text
Vue 科研工作台
  ├─ 研究目标 / 能力范围 / 联网策略 / 并发预算
  ├─ 用户隔离材料上传与预检
  ├─ 计划预览、运行轮询、取消、证据与警告展示
  └─ 人工反馈与学习提案审核
          │
          ▼
Research API
  ├─ ResearchPlanner ── 可解释领域识别 + DAG + review gates
  ├─ ToolPolicy ─────── deny-unlisted + network + approval
  ├─ RunManager ─────── 后台任务 + 全局并发车道 + 取消
  └─ ResearchRuntime
       ├─ DAG 波次调度 / timeout / retry
       ├─ Artifact intake
       ├─ Evidence review
       ├─ Experimental design
       ├─ Data analysis & visualization
       ├─ Research writing
       └─ Integrity & ethics check
          │
          ▼
SQLite: runs / steps / evidence / artifacts / feedback / proposals
```

### 稳定数据契约

- `ResearchRun`：目标、计划、策略、预算、进度、证据、最终聚合结果和取消标记。
- `ResearchRunStep`：能力、依赖、输入、状态、输出、警告、尝试次数、置信度和耗时。
- `ResearchArtifact`：用户、运行、相对路径、媒体类型、大小、SHA-256、预检摘要；API 不暴露物理路径。
- `AgentFeedback`：评分、人工接受状态、纠正和标签。
- `LearningProposal`：来源运行、理由、拟议变更、证据、待审核/应用/拒绝/隔离生命周期。

## 5. 核心科研场景

### 文献检索与分析

- 接受明确查询或已有结构化文献记录。
- 批量检索 PubMed，按 DOI → PMID → 标题键去重。
- 输出 `evidence_id`、PMID/DOI、作者、年份、摘要片段、定位链接和质量旗标。
- 只做检索/摘要级主题提取；正式系统综述仍要求全文筛选、偏倚评估、双人复核和方案注册。

### 实验设计辅助

- 先定义 population、intervention/exposure、comparator、outcome，而不是直接给样本数。
- 明确随机/可比性策略、盲法、批次/混杂、排除与缺失规则、多重比较。
- 样本量只给计算路径，不在缺少效应量和变异时虚构数字。
- 按人的研究、动物研究和一般数据研究触发伦理门，并推荐 CONSORT/STROBE/ARRIVE 等报告规范。

### 数据处理与可视化

- CSV/TSV 有界扫描 50,000 行，推断数值/文本类型、缺失率、基本分布和质量旗标。
- 对首个数值列生成直方图预览并作为有 SHA-256 的输出材料持久化。
- 统计技能拒绝非有限值、常数相关序列、错误 P 值、配对长度不一致和未识别检验；Welch t 检验作为非配对默认。
- 输出提醒要求效应量、置信区间、样本量、模型假设和多重比较策略。

### 科研写作支持

- 输出章节结构和每节最低信息要求。
- 生成主张—证据矩阵；每个事实主张必须绑定 evidence_id/locator。
- 无来源时只给脚手架并标记 `[待引证]`，不生成虚构 DOI 或“已完成综述”。

### 学术规范与伦理

- 检查定量主张无引用、只报告 P 值、观察性研究强因果措辞、人的/动物研究缺少伦理要素、主张无证据映射。
- 明确说明本地规则不是抄袭语料库，不能输出“原创率/查重率”。
- 结果用于预检，不能替代伦理委员会、统计师、期刊编辑或领域专家。

## 6. 决策与资源调度

1. 规划器按显式选择优先；未选择时才使用可解释关键词推断。
2. 有材料时自动增加 `artifact_intake`，数据分析依赖预检。
3. 实验设计可依赖文献；写作依赖已有文献/实验/数据；规范检查依赖写作。
4. 执行前验证步骤唯一性、能力是否注册、依赖是否存在、DAG 是否有环、步骤是否超预算。
5. 只有依赖进入终态的步骤可执行；同一波次最多使用单任务并发上限，全进程再受全局车道限制。
6. 每个能力拥有 timeout、retry、network、risk、modalities 和 cost metadata；策略拒绝会持久化为 `blocked`，不会伪装成完成。
7. 最终结果聚合置信度、warnings、失败/阻止步骤、review gates 和 evidence count。

默认资源边界：最多 20 个材料、单文件 25 MiB、context 512 KiB、PDF 最多提取 40 页/100,000 字符、表格最多扫描 50,000 行、证据最多持久化 200 条、单任务并发 1–4、全局能力并发 4。

## 7. 性能优化

- PubMed 从 `1 次 esearch + N 次 efetch` 改为 `1 次 esearch + 1 次批量 efetch`，网络往返复杂度由 O(N) 降为 O(1)，本地解析仍为 O(N)。
- 表格采用流式行扫描和在线均值/方差，不把完整 CSV 加载进内存。
- PDF、表格剖析和 Matplotlib 绘图通过线程卸载，避免阻塞 API 事件循环。
- 计划中无依赖的步骤按波次并发；并发和重试有硬上限，避免失控扇出。
- Skill 执行日志从无界原始输入/输出列表改为最多 500 条、只记录形状/键并脱敏。
- 新增用户+时间、用户+状态、运行+顺序等索引，支持桌面轮询和历史列表。

可用 `python scripts/benchmark_research_runtime.py` 复跑本地微基准。微基准只衡量确定性本地路径，不把网络服务时间伪装成框架性能。

2026-08-11 在当前 Windows/Python 3.13 环境的实测基线：完整范围规划 1,000 次共 0.0306 秒（0.031 ms/次）；200 条证据归一化 200 次共 0.6532 秒（3.266 ms/次）；50,000 行、4 列 CSV 流式剖析 3 次共 1.8291 秒（609.693 ms/次）。这些数值用于发现本地回归，不代表 PubMed 或模型提供方延迟。

## 8. 已知边界与后续扩展

- 图像当前只做安全存储与技术元数据；需要在 Provider 层增加带模态声明的视觉模型 fallback 列表，才能做语义解释。
- PDF 只抽取可读文本；扫描版 PDF 需要可审计 OCR 能力。
- 文献质量评估尚未实现 RoB 2、ROBINS-I 或 GRADE 的结构化双人流程。
- 样本量计算需要用户提供效应量/方差/设计效应后，接入按研究设计验证的统计模块。
- “学术规范检查”不连接商业查重库；若未来接入，必须解决数据授权、隐私、保留期限和机构合同边界。
- 当前后台队列为桌面单进程实现。多机部署应把相同运行契约迁移到持久队列，但不能改变用户隔离、策略和证据语义。
